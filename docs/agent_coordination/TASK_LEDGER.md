### Phase 4 RED mechanical schema addendum（不改变冻结科学协议）

1. `coordinate_id = SHA256(typed_canonical({sequence_digest,checkpoint,reveal_mode,reveal_seed,topology_digest,ratios,cadence_slots=4,time_limit=80,checker_version}))`。
2. `config_digest = SHA256(typed_canonical({method,role,horizon,prefix,requested_k,risk_lambda,phase3b_recipe_digest,h1_model_digest,slot_duration_ms=1.0,cooperative_deadline_ns,checker_version}))`；actual K是stage outcome，不进入config。
3. 主键/排序：validation `(coordinate_id,method,horizon,prefix,risk_lambda)`；test episode `(coordinate_id,method)`；events `(coordinate_id,method,event_index)`；timing `(coordinate_id,method,component_order)`；sequence `(sequence_id,method_order)`。coordinate、method、component的order均使用协议固定列表/索引，不按locale。
4. 选择链从`raw_validation_metrics`开始：validation raw→30-config/primary selection。test链为execution events→test episode→test sequence→conditions1--8→summary；不声称validation episode有action ledger。
5. published successful artifact中的`unreachable_od_count`必须为0；positive unreachable在row publication前fail closed/HOLD。任何published非零值或相关event均拒绝，因此该counter由成功artifact不变量重算为0。
6. `event_payload_digest = SHA256(typed_canonical({event_index,slot,stage,state_version_before,state_version_after,plan_revision,event_kind,reason,observation_digest,residual_state_digest,support_digest,requested_k,actual_k,batch_index,batch_count,action_count,local_token_ordinal,truth_binding_digest,edge_index,before_distance,after_distance,commit_legal,elapsed_ns}))`，只取已落CSV列，无隐藏preimage。
7. event reason域：start/proposal/batch/action=`NONE`；plan=`initial|reveal|exhaustion|invalidation`；discard=`reveal|invalidation`；wait-latch=`no_common_action`；checker reject=`type_error|stale_observation|unrevealed_token|duplicate_token|edge_range|source_possession|destination_possession|edge_capacity|shared_group|other_rejected`；end=`complete|discrete_timeout|wall_timeout|illegal|lower_bound_complete|lower_bound_timeout`。
8. 非适用sentinel：string=`NONE`、digest=`000...000`(64 zeros)、identity/index/distance/state/slot/stage/revision=`-1`；count与elapsed=`0`；noncommit `commit_legal=false`。event-kind专项测试固定哪些字段可非sentinel；连续event index与start/end唯一。
9. artifact hash图无环：manifest不进入自身任何hash map；summary scientific combined只覆盖model+五raw tables（validation、episode、sequence、events、timing），排除manifest/summary；manifest logical map覆盖model+五raw+summary并保存`summary_sha256`，仍排除manifest；manifest file SHA只由Main/Supervisor外部报告。
10. event transaction与结束槽位规则：同一成功batch严格记录为`proposal_bound -> action_committed[proposal order] -> batch_committed`；各action row是该原子事务的描述行，`state_version_before=state_version_after=v`，最终batch row是唯一状态跃迁行`v -> v+1`，其`action_count`必须等于紧邻且同slot/stage/revision/batch的action行数。相邻事件的状态必须连续；无状态语义的start/end使用`-1/-1`，其他非commit事件使用`v/v`。checker拒绝记录`proposal_bound(v/v) -> checker_rejected(v/v) -> episode_end(illegal)`，拒绝后不得出现batch/action/fallback/plan。`episode_end.slot`是已完整执行的slot数/下一slot cursor：初始已完成为0；slot `s`成功commit后完成为`s+1`；离散耗尽为80；checker在slot `s`原子提交前拒绝或wall deadline在该slot完成前触发为`s`。聚合`completion_slots`只在完成时等于end cursor，任何未完成（discrete/wall/illegal）均为81；因此validator按`reason`联合检查end slot、completion、legality与timeout，而非笼统要求二者相等。lower-bound start/end使用同一cursor约定。
11. 五stage动态K的唯一落盘规则：validation/test episode列使用`requested_k,actual_k_min,actual_k_max`，不再使用歧义单字段`actual_k`。execution event新增`requested_k,actual_k`，仅`plan_built`可非0：direct/lower为0/0；point为1/1；ordinary robust为8/8（stage0--3）与8/1（stage4）；oracle robust为8/去重后1..8且stage4=1。episode min/max从实际出现的全部plan事件重算，无plan为0/0；read-back必须把event stage、K、support digest与episode派生值联审。所有其他event K=0，且两个K字段进入event payload digest。
